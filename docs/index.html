Know what changed.
From the notch.

Ledge watches the network you're on and what your Mac exposes to it, and tells you in plain English the moment something changes. Open Wi-Fi. VPN off. A server suddenly reachable by everyone in the café. A new device at home. Something new set to run at login. It lives in the notch, so you see it; it's quiet the rest of the time.

The shape is the app. It opens out of the hardware notch when something changes and closes when you click anywhere.

What it tells you

Each of these is a change Ledge detects on its own and explains in one card, with what to do. Amber needs a decision; green is for your information. Nothing repeats within its quiet period, and nothing shows for networks you've marked as home unless it matters.

Open or weak Wi-FiYou joined a network with no encryption, or WEP/WPA1. Anyone nearby can read unencrypted traffic. It also tells you what name your Mac is announcing to them.
VPN disconnectedYour tunnel went down and you're on the network directly. Many VPNs, WireGuard and Tailscale included, never say so. Ledge also remembers where you normally use a VPN and nudges you when it's off there.
Router impersonationThe gateway's hardware identity changed while you stayed on the same network. That is what ARP spoofing looks like, and what a swapped router looks like. It says both.
HTTPS interceptionOptional. One request to apple.com when you join a new or open network: if the certificate isn't Apple's, someone in the middle is reading encrypted traffic. Sign-in portals are recognised and named as such.
Proxy set by the networkThe network configured a web proxy or auto-proxy for you. Normal at work, not on public Wi-Fi.
New trusted root certificateSomething added a certificate authority your Mac now trusts. Its owner can inspect your encrypted traffic. Expected for a corporate profile or a debugging proxy, nothing else.
An app is reachable from the networkA process started listening on all interfaces, so every device on the network can reach it. Dev servers bound to 0.0.0.0 are the classic case. Amber if the network is untrusted.
Sharing switched onRemote Login, Screen Sharing, File Sharing or Remote Management turned on, and other devices can now try to connect.
New device on your home networkOnly for networks you mark as Home. A device joined that Ledge hasn't seen there before, named by its maker from the IEEE vendor list.
New background itemA new login item, launch agent or launch daemon will run automatically from now on. The number one thing malware does; also what every installer does. Ledge names it and lets you judge.
New system extensionA kernel-level extension went active. VPNs, security tools and virtual cameras install these.
Unnotarized app launchedAn app opened that Apple hasn't checked for known malware. Fine for tools you trust; worth a second look for downloads.
SSH keys, cron, shell startup changedSomeone can log in with a new key; a scheduled job was added; your shell will run something new every time you open a terminal.
DNS resolver changedYour lookups moved to a different resolver, named when it's a known one (Cloudflare, Google, Quad9, the router, the VPN).
/etc/hosts changedThe file that overrides domain lookups was rewritten.

What it cannot do

Read this before you trust it. Ledge is awareness, not protection.

It doesn't block anythingBlocking needs Apple's network-extension entitlement, which needs a paid developer account. LuLu and Little Snitch do that job well; Ledge tells you what they can't.
It doesn't inspect trafficNo packet capture, no DNS filtering, no knowledge of what apps send. It reads your Mac's own state and the network's shape.
It isn't antivirusIt sees persistence and notarization, which is where most Mac malware shows up first, but it doesn't scan files.
It can't see privacy grantsWhich apps have Accessibility or Screen Recording rights is locked behind Full Disk Access. Ledge doesn't ask for it.
Wi-Fi names need LocationmacOS hides network names from apps without Location access. Ledge identifies networks by their router instead, and only asks for Location if you want names.
It isn't notarizedSame paid account. macOS blocks the first launch until you clear the download flag or click Open Anyway; the install steps below show both. The source is short enough to read and builds in seconds.

Lightweight by design

Network, DNS and proxy changes arrive as system events, so Ledge does nothing while nothing changes. The remaining checks run on minute-scale timers and each is a single short built-in command. No kernel extension, no daemon, no helper, one process, about 1 MB on disk plus a vendor table. Idle CPU is zero.

Install

  1. Download, unzip, and drag Ledge into your Applications folder.
  2. Ledge isn't notarized by Apple, so macOS blocks it on first launch. Open Terminal and run the line below. It removes the "downloaded from the internet" flag from this one app, nothing else:
    xattr -dr com.apple.quarantine /Applications/Ledge.app
    Prefer not to use Terminal? Double-click Ledge, then open System Settings › Privacy & Security, scroll to the bottom and click Open Anyway. On macOS 15 and later the old right-click → Open shortcut no longer works for apps like this one.
  3. Open Ledge. A shield appears in the menu bar; a dot on it means something needs attention. Nothing else happens until something changes. Click the notch for the status board.
  4. On your own Wi-Fi, use the menu-bar shield to Mark this network as Home, so Ledge announces devices that join it.

Why the extra step: notarizing an app requires a paid Apple Developer account, which this free project doesn't have. That is also why the checksum and the full source are published below, so you never have to take the download on trust.

Verify, or build it yourself

Every release publishes its SHA-256. The whole app is four Swift files and builds with Apple's command-line tools.

shasum -a 256 ~/Downloads/Ledge.zip
# 1.0.1 → 910b54152bfae4f121f28cc2a7dbc7815d7bb7df09f4031bf9e71be68a70a8ab

git clone https://github.com/Saidileepkumarmukkamala/ledge && cd ledge/app && ./build.sh && open Ledge.app

Everything Ledge reads comes from public macOS tools you can run yourself: route, ifconfig, arp, scutil, lsof, fdesetup, socketfilterfw, spctl, csrutil, sysadminctl, profiles, security, systemextensionsctl, sfltool, defaults. The only connection it can make is the optional HTTPS check, off by default.
